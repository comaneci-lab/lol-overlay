# 個別オーバーレイ開発ガイド

このガイドは、OBSのブラウザソースで動く個別オーバーレイを、リポジトリまたは配布版に追加するための資料です。HTML・JavaScript・CSSの基本形と、キル関与率（KPA）を表示する[動作サンプル](../examples/kpa/)を紹介します。横型・縦型の全体オーバーレイへの組み込みは対象外です。

## 1. 仕組み

```text
League of Legends
    ↓ Live Client Data API
LoLAPIGet.exe（ローカルプロキシ）
    ↓ /allgamedata 等
個別HTML → 個別JavaScript → 画面表示
             ↑
     共通CSS・個別CSSで見た目を調整
    ↓
OBSのブラウザソース
```

ローカルプロキシは `127.0.0.1:8888` で動き、実行ファイルと同じフォルダーの `html`・`js`・`css`・`assets` を配信します。ソースから起動する場合はリポジトリのルートが基準です。HTMLをファイルとして直接開かず、`http://127.0.0.1:8888/html/ファイル名.html` で開いてください。

### 既存コードの主な型

| 型 | 例 | 特徴 |
| --- | --- | --- |
| 個別JSで取得 | [分間CS](../js/LoL_CSPerMinute.js) | JSが `/allgamedata` を取得し、自分で描画・更新する。今回の雛形はこちら。 |
| 共通JSを利用 | [ゴールドチャート](../html/LoL_GoldChart_Overlay.html) | [LoL_Api.js](../js/LoL_Api.js) の初期化・選手データ更新と `playerdictupdated` イベントを利用する。 |
| 固有の処理を持つ | [試合アイテム・スキルオーダー](../js/LoL_MatchOrder.js) | 履歴や表示タイミングなど、機能ごとの状態を管理する。 |

共通JSを使う例では、HTMLで `LoL_Api.js` を先に読み込み、`initializeCommon()` の後に `refreshPlayerDict()` を呼び出して定期更新します。共通JSはチャンピオン・アイテム等のデータも読み込むため、単純な表示では必須ではありません。既存の各オーバーレイがすべて同じ初期化方式というわけではありません。

## 2. 共通フォーマット

個別オーバーレイは、次の3ファイルをひと組にすると管理しやすくなります。

| 役割 | 配置例 | 内容 |
| --- | --- | --- |
| HTML | `html/Dev_機能名_Overlay.html` | 表示領域、共通CSS・個別CSS・JSの読み込み |
| JavaScript | `js/Dev_機能名.js` | API取得、表示条件の判定、計算、DOM更新 |
| CSS | `css/individual/Dev_機能名_Overlay.css` | 個別の配置、サイズ、色 |

英数字・アンダースコアなどを使った、既存ファイルと重複しない名前にしてください。3ファイルの対応とHTML内の参照先を揃えます。オーバーレイのHTML・JS・CSSはLF改行で保存します。

基本的な処理の流れは次のとおりです。

1. HTMLに表示先を作り、表示前は `hidden` にする。
2. JavaScriptでプロキシからデータを取得し、HTTPエラーと `ok` を確認する。
3. ゲームモード、観戦モード、必要なフィールドを確認する。
4. データを表示用に変換して描画する。API由来の文字列は `textContent` で設定する。
5. 一定間隔で再取得し、失敗時や表示対象外のときは古い表示を隠す。通信の重複を避け、エラーはコンソールに出す。
6. CSSで透過背景、サイズ、文字を調整し、OBSのブラウザソースで確認する。

履歴を蓄積する機能では、試合終了・新しい試合・ブラウザソースの再読み込み時に状態をどうリセットするかも設計してください。雛形のKPAは毎回の現在値から計算するため、履歴は保持しません。

## 3. KPAサンプル

[examples/kpa](../examples/kpa/) に、配置先と同じディレクトリ構成で3ファイルを用意しています。

| サンプル | コピー先 |
| --- | --- |
| [Dev_KPA_Overlay.html](../examples/kpa/html/Dev_KPA_Overlay.html) | `html/Dev_KPA_Overlay.html` |
| [Dev_KPA.js](../examples/kpa/js/Dev_KPA.js) | `js/Dev_KPA.js` |
| [Dev_KPA_Overlay.css](../examples/kpa/css/individual/Dev_KPA_Overlay.css) | `css/individual/Dev_KPA_Overlay.css` |

3ファイルはそのままコピーして動かせます。HTMLは、コピー先の既存の `css/LoLOverlay.css` と `css/custom/LoLOverlay.custom.css` も読み込みます。雛形の名前は例なので、独自開発時はHTMLの参照先も含めて変更してください。

### 表示仕様

- 自チームの各選手の **(キル数＋アシスト数) ÷ 自チームの総キル数 × 100** を表示します。総キル数は自チームの各選手の `scores.kills` の合計です。
- チームの総キル数が0のときは `0%`、それ以外は小数第1位まで表示します。
- `CLASSIC`、`PRACTICETOOL`、`ARAM` のプレイ時に対応します。観戦時や対象外モードでは非表示です。
- 1秒ごとに取得します。試合のデータを取得できない場合、観戦判定や自チームを特定できない場合、必要なスコアが欠けている場合は非表示にし、取得・データのエラーをブラウザのコンソールに記録します。同じエラーが続く場合の重複ログは抑制します。
- 選手の表示順はAPIの `allPlayers` の順番です。選手名は `riotIdGameName`、`riotId`、`summonerName`、`championName` の順で利用可能なものを使用します。

たとえば自チームの総キルが10で、ある選手が2キル・3アシストなら `50.0%` です。集計にはAPIから取得できる現在値を使用します。

### 使用するデータ

`GET /allgamedata` の成功時は概ね次の形です。これは説明用の抜粋であり、実際のレスポンスには他のフィールドもあります。

```json
{
  "ok": true,
  "data": {
    "isSpectatorMode": false,
    "gameData": { "gameMode": "CLASSIC", "gameTime": 600 },
    "activePlayer": { "riotId": "Player#JP1" },
    "allPlayers": [
      { "team": "ORDER", "riotId": "Player#JP1", "scores": { "kills": 2, "assists": 3 } },
      { "team": "ORDER", "riotId": "Ally#JP1", "scores": { "kills": 8, "assists": 1 } },
      { "team": "CHAOS", "riotId": "Enemy#JP1", "scores": { "kills": 5, "assists": 0 } }
    ]
  }
}
```

`isSpectatorMode` はプロキシが付加する値です。自チームは `activePlayer.team` があればそれを使い、なければ `activePlayer` と `allPlayers` のIDを照合します。一意にチームを決められない場合は推測しません。取得失敗時には `{ "ok": false, "error": "..." }` のような応答もあるため、常に `data` があるとは限りません。

### 別の表示を作る

1. 3ファイルを別名にコピーし、HTMLのCSS・JS参照と表示先IDを変更します。
2. JSの `getKpaRows` を参考に、必要なフィールドを確認して表示用データを作ります。取得先が違う場合はURLも変更します。
3. `renderKpaRows` を参考に要素を作り、CSSのクラス名と合わせます。
4. 対応モード、観戦時の動作、取得失敗時の表示、更新間隔を機能に合わせて決めます。
5. 下記の手順で実際に確認します。たとえばキル・デス・アシスト一覧や、試合時間に応じた表示を作れます。

プロキシには `/playerlist`・`/activeplayer`・`/eventdata`・`/gamestats`、Data Dragon用の `/champions`・`/items`・`/summoner_spells`・`/runes`・`/champion/<名前>` もあります。実際の応答はブラウザで確認し、欠ける情報や試合モードごとの違いを考慮してください。

## 4. 実行・確認

1. リポジトリから上記の3ファイルを、実行ファイルと同じフォルダーの対応する場所へコピーします。配布ZIPに `examples` が含まれていない場合は、GitHubのリポジトリからサンプルを取得してください。リポジトリからPythonで起動している場合は、リポジトリのルートにコピーします。
2. LoL Overlayを起動し、対応モードの試合に参加します。
3. ブラウザで `http://127.0.0.1:8888/html/Dev_KPA_Overlay.html` を開き、選手名とKPAが表示されることを確認します。JavaScriptなどを変更したらページを再読み込みします。
4. OBSでブラウザソースを追加し、同じURLを設定します。KPAサンプルの幅・高さの目安は **360×230** です。表示が切れる場合はOBS側で調整してください。

アプリの管理タブの一覧に追加したHTMLが表示されない場合は、一覧を更新してください。アプリからOBSソースを追加する際、サイズ設定のないHTMLには既定の800×600が使用されます。推奨サイズを登録する方法は[OBS設定手順](OBS設定手順.md)を参照してください。

### 開発時の確認項目

- 試合中の自チーム、キル・アシスト、0キルの表示が正しい。
- 観戦時、対象外モード、試合データ取得失敗時に古い表示が残らない。
- OBSとブラウザで表示が切れず、背景透過が意図どおりである。
- ブラウザの開発者ツールで `Console` のエラーと `Network` の `/allgamedata` を確認する。

リポジトリのサンプルには自動テストもあります。Node.jsを用意し、リポジトリのルートから次を実行できます。

```powershell
node --test tests\test_kpa_example.cjs
```

## 5. 更新・配布時の注意

- 開発用の3ファイルは公式ファイルと別名にし、バックアップを取ってください。オーバーレイ更新は公開一覧にあるファイルを上書きします。同名のファイルが将来公式に追加されれば衝突する可能性があります。
- サンプルは開発用資料です。`examples/kpa` 内のままではプロキシから配信されず、公式オーバーレイ更新やビルド結果の `dist` に自動追加されません。配布ZIPへの追加は[リリース手順](リリース手順.md)を参照してください。
- `css/custom/LoLOverlay.custom.css` は公式オーバーレイ更新の対象外です。サンプルHTMLは個別CSSの後にこのファイルを読み込むので、必要に応じて見た目を上書きできます。
- オーバーレイ更新や配布版の入れ替え後は、独自ファイルとその参照先が残っているか確認してください。個人情報を含むゲームデータを外部へ送信する機能は、送信先や利用目的を確認してから追加してください。
